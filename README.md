## ما هذا المستودع

تطبيق أندرويد أصلي بلغة **Kotlin** و**Jetpack Compose** لتشغيل وإدارة الفيديوهات المخزنة على الهاتف — بدون إنترنت، بدون حساب، وبدون إعلانات. المشروع مكتمل الملفات ويُبنى مباشرة دون ملفات ناقصة أو خطوات يدوية.

| 20 | زر للعودة إلى المشغل التقليدي | زر `📺` ينقل إلى `PlayerScreen` |

### 2) المشغل التقليدي الكامل
`ui/player/PlayerScreen.kt`

- تشغيل/إيقاف، تقديم ±10 ثوانٍ (قابل للضبط 5–60)، شريط تقدم قابل للسحب.
- **الإيماءات:** سحب رأسي على اليسار = السطوع، على اليمين = الصوت، سحب أفقي = انتقال زمني، نقر مزدوج = ±مدة القفز، قرصة بإصبعين = تكبير حتى 4×، سحب بإصبعين = تحريك الصورة.
- **قفل اللمس** لمنع اللمس العرضي، و**قص/ملاءمة** لنسبة الأبعاد.
- **السرعة:** 0.25× → 4×.
- **الترجمة:** تعرض الترجمة المدمجة تلقائيًا مع تحكم بحجم الخط، ودعم إضافة ملف خارجي.
- **المسارات الصوتية:** قراءة المسارات من `Tracks` والتبديل بينها.
- **وضع التكرار:** لا / واحد / الكل.
- **معلومات الفيديو:** المدة، الحجم، الدقة، المجلد، النوع، المسار.
- **استئناف المشاهدة** من آخر موضع تلقائيًا.

### 3) المكتبة وإدارة الفيديوهات
`ui/library/LibraryScreen.kt` · `data/repo/VideoRepository.kt`

- قراءة كل فيديوهات الجهاز من **MediaStore** مع فهرسة: الاسم، المدة، الحجم، التاريخ، المجلد، الأبعاد، نوع MIME.
- **إضافة مجلدات** خارج MediaStore عبر **SAF** (`OpenDocumentTree`) مع فحص متكرر للمجلدات الفرعية، وحفظ إذن دائم للمجلد.
- **بحث فوري** بالاسم أو المجلد، **فرز** بستة معايير، **عرض شبكي/قائمة**، **فلاتر مجلدات**.
- **صور مصغّرة حقيقية** تُستخرج محليًا عبر `MediaMetadataRetriever` مع ذاكرة `LruCache` محسوبة على ذاكرة الجهاز.
- **قسم «استكمال المشاهدة»** يعرض ما توقفت عنده مع نسبة الإنجاز.
- **إدارة الملفات:** إعادة تسمية، حذف، نسخ إلى مجلد، مشاركة، فتح بتطبيق آخر، إخفاء من المكتبة — كلها عبر واجهات النظام الرسمية وتحترم صلاحياته.
- **معالجة أخطاء حقيقية:** إذا رفض النظام العملية تظهر رسالة واضحة، ولا يُدَّعى النجاح.

### 4) المفضلة والسجل وقوائم التشغيل
`data/db/*` · `data/repo/UserDataRepository.kt`

- **Room** بخمسة جداول: `progress` (التقدم + عدد مرات التشغيل)، `favorites`، `hidden`، `playlists`، `playlist_items`.
- المفضلة، سجل المشاهدة (مرتب بالأحدث)، قوائم تشغيل بإنشاء/حذف/إعادة تسمية/إضافة/إزالة، وتشغيل القائمة كاملة بالترتيب.
- حفظ الموضع **لكل فيديو على حدة**، ويُصفَّر تلقائيًا عند بلوغ آخر 3 ثوانٍ حتى يبدأ الفيديو من جديد في المرة القادمة.

### 5) التشغيل في الخلفية والنافذة العائمة وPiP
`service/PlaybackService.kt` · `service/FloatingPlayerService.kt`

- **إشعار وسائط** عبر `MediaSessionCompat` يعرض اسم الفيديو والزمن وأزرار التشغيل/الإيقاف/التالي/الإغلاق، مع `ForegroundService` من نوع `mediaPlayback` (متوافق مع سياسات أندرويد 14).
- **نافذة عائمة حقيقية** فوق التطبيقات الأخرى عبر `TYPE_APPLICATION_OVERLAY` و`SYSTEM_ALERT_WINDOW`: مشغل مصغّر كامل مع تحكم، شريط تقدم، أزرار تقديم/ترجيع، تحريك النافذة بالسحب، وتوسيعها إلى التطبيق.
- **صورة داخل صورة (PiP)** مع نسبة أبعاد، ودخول تلقائي عند مغادرة التطبيق إذا كان الخيار مفعّلًا.
- **فتح ملف فيديو من تطبيق آخر** مباشرة عبر `intent-filter` لـ `video/*`.

### 6) الإعدادات
`ui/settings/SettingsScreen.kt` · `data/prefs/Prefs.kt`

محفوظة في **DataStore**: الوضع (داكن/فاتح/النظام)، لون الواجهة (5 ألوان)، السرعة الافتراضية، مدة التقديم، الاستئناف التلقائي، تفعيل كل إيماءة على حدة، قفل اللمس، PiP، التشغيل في الخلفية، حجم الترجمة، إدارة مجلدات المكتبة، ومسح السجل والصور المصغرة.

## البناء والتشغيل

### المتطلبات
- **JDK 17** (مطلوب — JDK 21 غير مدعوم مع AGP 8.6)
- **Android SDK** بمنصة `android-35` و`build-tools 35.0.0`
- Gradle 8.7 (أو استخدم Gradle Wrapper إن توفّر)

### الخطوات
```bash
# 1) استنساخ
git clone https://github.com/anss94022-oss/Saddam-Player.git
cd Saddam-Player

# 2) تحديد مسار SDK (ملف محلي لا يُرفع للمستودع)
echo "sdk.dir=/path/to/Android/Sdk" > local.properties

# 3) البناء
gradle assembleDebug

# 4) الناتج
# app/build/outputs/apk/debug/app-debug.apk
```

### التثبيت على الهاتف
```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
أو انسخ ملف APK إلى الهاتف واسمح بالتثبيت من مصدر غير معروف عند الطلب.

### البناء التلقائي
سير العمل `.github/workflows/main.yml` يبني APK عند كل دفع إلى `main`، ويرفع الملف كـ Artifact باسم **Saddam-Player-debug-apk** يمكن تنزيله من تبويب **Actions** ثم صفحة التشغيل الأخير.

## الأذونات المطلوبة وطريقة منحها

| الإذن | متى يُطلب | ماذا يحدث لو رُفض |
|---|---|---|
| `READ_MEDIA_VIDEO` (أندرويد 13+) / `READ_EXTERNAL_STORAGE` (أندرويد 12 وأقدم) | عند أول تشغيل | تبقى المكتبة فارغة، ويمكن إضافة مجلد محدد بدلًا منه |
| `SYSTEM_ALERT_WINDOW` (الظهور فوق التطبيقات) | عند اختيار «نافذة عائمة» | يفتح التطبيق شاشة الإعدادات لتمكينه يدويًا |
| `POST_NOTIFICATIONS` (أندرويد 13+) | عند التشغيل في الخلفية | يعمل التشغيل لكن دون عناصر تحكم في الإشعار |

خطوات المنح: **الإعدادات → التطبيقات → SDM VP → الأذونات**، أو اتبع الطلب الذي يظهر داخل التطبيق.

> مجلدات SAF لا تحتاج أي إذن إضافي: صلاحية المجلد تُمنح من نظام الملفات نفسه وتُحفظ بعد إعادة التشغيل.

## دعم صيغ الفيديو — توضيح صريح

التشغيل يتم عبر **ExoPlayer (Media3)** وهو المحرك الرسمي من Google. الصيغ المدعومة فعليًا تعتمد على **مرمّزات الجهاز**:

- **مدعوم دائمًا:** MP4 / M4V / 3GP (H.264 + AAC)، WebM (VP8/VP9 + Opus/Vorbis)، MKV (بما فيه H.264/HEVC/VP9)، TS/M2TS، MPEG-TS، FLV (H.264).
- **مدعوم على معظم الأجهزة الحديثة:** HEVC/H.265، AV1 (من أندرويد 10+ على أجهزة تدعمه عتاديًا)، AC-3/E-AC-3 (أندرويد 11+)، DTS (حسب الجهاز).
- **غير مضمون:** WMV/VC-1، RMVB، بعض ملفات AVI القديمة بترميزات قديمة.

**لا يدّعي التطبيق دعمًا غير حقيقي:** عند فشل الترميز تظهر رسالة واضحة («تعذر تشغيل هذا الملف. قد تكون الصيغة أو الترميز غير مدعوم على هذا الجهاز») مع زر إعادة المحاولة، بدل التعطل الصامت.

لماذا ExoPlayer وليس LibVLC؟ لأن ExoPlayer لا يضيف حجمًا كبيرًا للتطبيق، متوافق تمامًا مع Media3 وPiP وإشعارات الوسائط ومعالجة صلاحيات التخزين الحديثة في أندرويد. إذا كانت لديك ملفات بصيغ نادرة (RMVB/WMV)، فالحل العملي هو تحويلها بـ FFmpeg أو استخدام مشغل بديل لتلك الملفات تحديدًا.

## الخصوصية

كل ملفات الفيديو تُقرأ من الجهاز فقط. **لا يوجد أي اتصال بشبكة، ولا تحليلات، ولا مفاتيح API، ولا خدمة مدفوعة.** المفضلة والسجل وقوائم التشغيل والإعدادات تُخزَّن محليًا في Room وDataStore، ويمكن مسحها من شاشة الإعدادات.
